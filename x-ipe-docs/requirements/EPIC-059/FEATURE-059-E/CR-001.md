# Change Request: CR-001 — Extractor-Driven Librarian Research Loop

> Created: 2026-04-27
> Status: Documented
> Classification: Modification to FEATURE-059-E
> Related Feature: FEATURE-059-E

## Request Details

**Requestor:** Human product owner
**Date Received:** 2026-04-27
**Priority:** High

## Description

Update the Knowledge Librarian workflow so construction requests follow the extractor-driven workflow described in `x-ipe-docs/ideas/041. CR-Rebuild Knowledge Skills/idea-summary-v1.md`. The Librarian must use extractor skills to learn the overview before rubric design, must use extractors again when the constructor needs more information during refinement, and must support a `deep_research` option with `1_round`, `3_round`, and default `smart` modes.

## Business Justification

The Librarian is intended to coordinate constructors and extractors, not manually inspect source material or synthesize missing context itself. If the overview and refinement gaps bypass extractor skills, the resulting constructed knowledge is less auditable, less reusable, and less aligned with the 格物致知 pipeline. Deep-research modes make iteration intent explicit while preserving a default smart mode that keeps researching until the rubric is fully satisfied or a concrete blocker prevents more progress.

## Impact Analysis

### Classification

**Type:** Modification to FEATURE-059-E

**Reasoning:** FEATURE-059-E already owns the Knowledge Librarian orchestrator, constructor-driven workflow, overview extraction, critique loop, and skill structure. This CR refines those existing responsibilities rather than adding a new workflow or user-facing capability.

### Comparison Matrix

| Aspect | CR Requirement | Existing FEATURE-059-E Behavior |
|--------|----------------|----------------------------------|
| Overview | Mandatory extractor `extract_overview` before rubric design | Overview extraction exists but can be interpreted loosely |
| Gap handling | Constructor gap requests must be fulfilled by extractors using newly discovered context | Replan loop asks constructor for gaps, but extractor-driven discovery is not explicit enough |
| Iteration control | `deep_research: 1_round \| 3_round \| smart`, default `smart` | Fixed `max_iterations: 3` guard |
| Success target | Smart mode aims for 100% rubric satisfaction | After 3 iterations, partial quality is accepted |

## Proposed Approach

1. Document this CR as a FEATURE-059-E modification.
2. Update FEATURE-059-E spec/design to make extractor overview mandatory for construction.
3. Update gap refinement so constructor requests are fulfilled by extractors and can expand based on newly discovered sources.
4. Replace fixed `max_iterations` input with `deep_research`, accepting aliases `1 round` and `3 round` but normalizing to `1_round` and `3_round`.
5. Define smart mode as default: iterate while rubric satisfaction is below 100% and actionable extractor-backed gaps remain; stop only on 100% satisfaction or a documented blocker/safety cap.
6. Update the Knowledge Librarian skill via the `x-ipe-meta-skill-creator` candidate workflow and merge only after validation.
