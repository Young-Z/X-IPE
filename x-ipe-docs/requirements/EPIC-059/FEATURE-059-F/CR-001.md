# Change Request: CR-001 — KG Support for Memory Ontology Layout

> Created: 2026-04-27
> Status: Documented
> Classification: Modification to FEATURE-059-F
> Related Feature: FEATURE-059-F

## Request Details

**Requestor:** Human product owner
**Date Received:** 2026-04-27
**Priority:** High

## Description

Update the Knowledge Graph viewer so KG supports the new Memory and ontology structure. The graph should load data from `x-ipe-docs/memory/.ontology/` using the new schema, instances, vocabulary, and relation files, while `.ontology` files remain transparent to end users. UI and processing logic should refer to user-facing Memory / Knowledge Graph data instead of old KB graph files or ontology storage files.

## Business Justification

Memory replaced the old Knowledge Base concept, and the knowledge pipeline now persists ontology data under Memory. If KG still expects the old `knowledge-base/.ontology/.graph-index.json` structure or exposes ontology implementation files in UI, users cannot explore newly learned Memory and are forced to understand internal storage. The KG viewer must become a user-facing visualization of Memory relationships, not a browser for ontology files.

**Reasoning:** KG viewer, auto-load behavior, unified graph endpoint, and ontology migration are already in scope for FEATURE-059-F. This CR refines that existing feature to support the latest Memory ontology layout and transparency requirement. It does not add a new user role, standalone workflow, screen, or API family.

### Conflict Analysis

**Conflicts Found:** Yes

| # | Type | Affected Feature | Severity | Classification | Description |
|---|------|------------------|----------|----------------|-------------|
| 1 | specification | FEATURE-058-E | Medium | expected | Original KG viewer spec describes users selecting `.jsonl` graph files from `knowledge-base/.ontology/`, which conflicts with transparent Memory ontology. |
| 2 | specification/design | FEATURE-059-F | High | expected | FEATURE-059-F already removes the graph sidebar but still assumes `.graph-index.json`, root graph JSONL files, and raw graph names. |
| 3 | implementation | `OntologyGraphService` | High | expected | Service depends on `.graph-index.json` and `<graph>.jsonl`; it cannot synthesize KG from Memory subdirectories when the old index is absent. |
| 4 | dependency | FEATURE-059-D / Memory ontology writer | Medium | unexpected | Relation chunks may be observed under `.ontology/instances/_relations.NNN.jsonl`, while the spec/service expect `.ontology/relations/_relations.NNN.jsonl`. |
| 5 | implementation | KG search | Medium | expected | Text search and BFS search assume old graph files and `entity.properties`, not nested `props` records. |
| 6 | UI | `ontology-graph-viewer.js` | Medium | expected | Empty states/status/scope text can mention ontology or graph-file internals instead of Memory graph data. |

**Unexpected Conflict Resolution:**
- Support both `.ontology/relations/_relations.NNN.jsonl` and `.ontology/instances/_relations.NNN.jsonl` during migration.
- Keep endpoint names for compatibility but change user-facing messages and graph labels to Memory/Knowledge Graph terminology.

**Mitigation Strategy:**
- Add a fallback/new primary loader in `OntologyGraphService` that synthesizes a user-facing Memory graph when `.graph-index.json` is absent.
- Preserve old graph-index/root JSONL support to avoid breaking existing test fixtures and legacy ontology data.
- Update specs/designs to mark graph-file selection as superseded by FEATURE-059-F/CR-001.

- `x-ipe-docs/memory` as the active Memory root

## Proposed Approach

1. Document CR-001 as a FEATURE-059-F modification and update affected specs/designs.
2. In `OntologyGraphService`, keep legacy `.graph-index.json` handling, but synthesize a Memory graph when the old index is absent and new ontology subdirectories exist.
3. Normalize event records with nested `props`, preserving class, lifecycle, memory entry id, source files, synthesizer metadata, and custom properties in node data.
4. Read relation chunks from both `.ontology/relations/` and `.ontology/instances/`.
5. Parse vocabulary JSON concepts as user-facing concept nodes.
6. Update search to use the synthesized graph model when legacy graph files are absent.
7. Update UI messages and graph labels so end users see Knowledge Graph / Memory wording instead of `.ontology` implementation details.

## Mockup Impact

**UI/UX Change:** Yes, but no new mockup is required for this refinement. The existing KG viewer mockup remains visually applicable; this CR changes labels/content semantics and removes reliance on raw graph-file scopes already addressed by FEATURE-059-F.
