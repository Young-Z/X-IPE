# Lessons Learned

## LL-001 — Board instructions must match executable CLI and schema

- Status: raw
- Severity: major
- Task: TASK-6747
- Date: 2026-10-13
- Trigger: agent-observed failure while registering a planning study.

### Context

The board skill documents creation with --title/--description/--assignee, updates with a positional task ID and --status, queries with --assignee, and autogenerated task IDs. The current scripts use JSON contracts instead.

### Observed versus expected

- Observed: --help exposed --task; the first JSON invocation using the documented title/assignee model failed with SCHEMA_VALIDATION_FAILED: Missing required field: task_id.
- Expected: following the skill examples creates a valid task, and documented fields/options match the scripts.
- Additional observed issue: queries default to a one-week window. An all-date query found older in-progress tasks omitted by the first query. Nickname/ownership checks must not use the one-week default.

### Verified ground truth

- [Creation parser](.github/skills/x-ipe-tool-task-board-manager/scripts/task_create.py#L29-L32): --task JSON; caller supplies task_id.
- [Actual schema](.github/skills/x-ipe-tool-task-board-manager/scripts/_board_lib.py#L46-L58): task_id, task_type, description, role, status, created_at, last_updated, output_links, next_task. Timestamps are managed by the script.
- [Query parser](.github/skills/x-ipe-tool-task-board-manager/scripts/task_query.py#L24-L33): --task-id or list filters including --range all; no --assignee flag.
- [Update script](.github/skills/x-ipe-tool-task-board-manager/scripts/task_update.py): --task-id and --updates JSON.
- A corrected create/query/update sequence successfully registered and started TASK-6747.
- Canonical terminal task status is completed; done is accepted as an alias by the library.

### Proposed improvement

- Type: update_instruction + new_ac.
- Update the board skill through the creator candidate workflow; no live skill edit was made in this study.
- Either document the verified script contract or implement/test the advertised convenience CLI deliberately. Do not silently mix them.
- Add executable documentation examples tested in a temporary project.
- Make registration/resume an idempotent shared lifecycle operation; define collision-safe ID allocation rather than relying on an unlocked max-ID scan.
- Add a scenario in which an in-progress task older than one week must appear in ownership/nickname checks.
- Validate documented status and field names against the library schema and consumers.
