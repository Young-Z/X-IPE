# Refactoring techniques — bounded preservation

## Analysis context and inputs

Use actual analysis result refactoring_scope, code_quality_evaluated,
refactoring_suggestion and refactoring_principle plus report_path. Keep dependencies
and scope_expansion_log as inspection evidence, separate from write authority.
Quality baseline absence is an explicit gap, not proof of poor quality or permission
to create global documentation. The integration reference defines truthful scoped
adapters for installed full_analysis/full_sync contracts.

Named gap → source/parent quality goal → chosen principle/means → affected
structure → unchanged behavior check → before/after comparison. Principles are
justification, not automatic obligations to split every file or create classes.
No arbitrary score/threshold or stakeholder gain invented from line count.

## Plan and test design

For each bounded phase record allowed paths, exact structural change, named goal,
source/AC/type, risk/caller boundaries, preservation checks, affected references,
trade-off and restoration evidence. Alternatives select one viable means; all-required
subgoals keep their necessary checks. Use actual AAA: Arrange approved context,
Act original public behavior, Assert unchanged contract; one assertion per clause.
Refactor preservation baseline is expected green; no bug invented to obtain red.

Choose relevant happy/error/boundary/import/data/security/concurrency/resource
cases from actual impact, not blanket percentages. Unknown public consumers block
unsafe YAGNI deletion. API names/re-exports/serialization/error semantics remain
externally-visible behavior. Key structural design impact updates only approved
affected design/Change Log; changed acceptance needs prior actual human CR authority.

## Incremental execution and safe restoration

Capture owned prework bytes/hashes and relevant baseline tests before each phase.
Apply approved structural change through selected enabled tool or creator route
and run unchanged preservation tests. Tools return operation_output, not task
outputs; preserve actual files, assert-level results, lint and errors.

A public import fails after extraction: preserve the public re-export rather than
rewriting the assertion to a new internal path. A changed result means stop and
inspect, not classify as a legitimate refactor test update. Restore only owned
phase bytes after concurrent-edit check. No forced commit/checkpoint, reset,
stash, branch switch, earlier-revision checkout or destructive global revert.
Default no commit even if task completes; release/Git work needs separate authority.
After three failed attempts return partial evidence and blocker to one owner.

## Affected reference sync

Mode-aware sync consumes actual analysis findings. Local updates only existing
affected paths/components/design references; study is read-only findings; broad
includes justified larger dependencies and integration verification. Missing docs
remain not_found/gaps. Requirements/specification discrepancies are contract
questions, not permission to rewrite intended behavior to match code. Do not skip
or weaken failing assertions or add unrelated scope to satisfy a coverage target.

Track actual updated requirements/specification/design paths and counts, including
zero. Preserve unrelated IDs/history/source bytes. A combined authorized report
may hold analysis/sync/plan/verification sections if actual consumer tags accept
it; no speculative separate documents or app completion invented.

## Quality validation

Compare named baseline with after evidence using the same inspected scope and
method. Quantitative examples: repeated decisions or measured dependency cycles.
Qualitative examples: formerly mixed responsibilities now independently changeable,
with a concrete responsibility/caller map and trade-off. Either requires evidence,
not a judgement number chosen to imply improvement. Study returns recommended,
not achieved change. No synthetic metrics from approvals or passing document tests.

Run planned domain tests/build/lint. Broad includes relevant integration/full
suite; local targets risk; pre-existing failures remain named and new regressions
block. Applicable coverage uses actual comparable commands/scopes/results; absent
measurement is not maintained. Bind source/test/design/config/review hashes;
changes invalidate affected evidence, not every unrelated legacy check.

## Tracing instrumentation

Preserve moved/renamed decorators, levels and redaction semantics; renamed trace
identities may affect observable consumers and require checks. Adding tracing is
not automatically behavior-preserving. Inspect tracing_enabled and infrastructure;
disabled/absent requires no installation/instrumentation. Enabled relevant new
instrumentation needs explicit scope, the tracing tool contract and rerun tests.
No secret/PII exposure or forced annotations just to claim a quality score.

## Safety checkpoints

Analysis output or disclosed adapter must exist before targeted sync. Baseline
and authority precede mutation, not study. Public-contract expansion needs actual
human CR authority before behavior change; DAO guidance is not permission.
Use self-checks and targeted tests by default; independent review is required only for an explicit request or concrete high-risk uncertainty under the shared single-loop policy. Reuse suitable current review; missing required review blocks the affected claim, not drafting. Creator candidate_ready is not published.
Current app mandatory action/context/tag/readback gates remain per integration.

## Output guidance

Use only the entry's original Output Result; this reference is plain guidance,
not an alternate Output schema. Preserve category, status, conditional next tasks,
process_preference.interaction_mode, execution_mode, workflow.name, links,
feature_id, full refactoring_summary and code_quality_evaluated nested fields.
Retain original count fields, principles applications/areas and goal states;
actual paths only. Supplied optional/dynamic legacy fields pass through unchanged.

The designated quality_score_before/after fields are strings: comparable justified
numeric strings or not measured. Do not put that sentinel in a numeric tool score,
add synthetic aggregates or invent coverage status. Actual null is explicitly
allowed for unmeasured coverage sides/status; strict legacy consumers rejecting it
have a compatibility gap, not coerced success. Read integration. Report findings,
trade-offs, verification and unmeasured stakeholder outcome separately from task
schema. Return full actual tool output to one owner; never execute successors.
